# 2026-09-09 单台接线与受控故障复位

结果：确认当前只有一台 Diamond 驱动器，用户确认电机与编码器反馈线已连接。PREOP 下通过 SDO 发送一次 `6040:00=0 → 128 → 0`，三次写入均获成功响应，但随后读取和独立复查仍为 `6041=0x0208`、`603F=0x738A`。尚未验证故障清除。

## 操作范围

- 单台位置 0，Vendor `0x00418108`、Product `0x00009252`、Revision 1，与配置匹配。
- 主站保持 Idle / Active: no，从站保持 PREOP；没有申请或启动周期 PDO 应用。
- 写入前重新确认从站数量、身份检查结果、AL 状态、CiA402 Fault，以及控制字未请求上电/使能。
- 只写三个 `UINT16` 控制字 `0x0000`、`0x0080`、`0x0000`，两次间隔约 100 ms。未写使能、模式、目标、PDO 映射或保存参数。
- 正常及异常退出均卸载本次加载的 `ec_generic`、`ec_master`，最终检查模块均不存在。

[CiA402 控制字说明](https://drives.novantamotion.com/summit/0x6040-control-word)规定故障复位使用 bit 7 上升沿，复位与使能是不同状态转换。本次验证的是该标准脉冲在本机 PREOP/SDO 路径上的行为；没有确认它等同于 PMAC 在线运行时的 `#1k`、`#1j/` 整个流程。

## 邮箱响应问题

内核日志记录 `Received unknown response while uploading SDO 0x6040:00`，收到的数据包含对象描述文字 `Rotation Direction Setting`，同时出现 `Reception of CoE SDO description request failed`。这次失败不是“写复位被拒绝”：三个写操作均已经成功返回，失败发生在后续读取。

本地 IgH 源码 `master/fsm_master.c` 会在 PREOP 等待后自动读取 SDO 字典，外部上传由另一从站状态机处理。日志提示对象字典读取与外部请求的邮箱响应分配可能存在冲突，尚未完成互斥问题修复或长期复测。当前脚本遇到该错误即停止，绝不自动重发复位。

## 解释与下一步

`0x738A` 在 [Diamond 厂家手册 PDF 第 102 页](https://innodrive.ru/upload/iblock/08d/ktk23ukimoo3b3efav665ctg469cf02v.pdf#page=102)对应编码器通信 CRC 错误，但这次不能区分故障原因仍存在、参数不匹配、报警锁存或 PREOP 下复位未由驱动器状态机执行。SDO 写入获得响应，只证明对象写入被接受，不能证明内部故障恢复已完成。

先核对准确型号/固件、主站类型参数 `0x2005` 和编码器参数，确认 PREOP 下控制字处理要求；处理邮箱响应互斥，并准备明确的 PDO 分配/映射。随后建立禁止使能的周期通信，再验证故障恢复。不能直接接续 `6 → 7 → 15` 使能序列，尤其当前 `6060/6061=0`，也未验证实际位置有效。

当前新增 `scripts/reset_fault_once.py` 是独立现场测试入口，正常的 `probe_connected.py` CLI 仍只读取。复位脚本退出码 0 表示流程完成，必须检查 `fault_reset` 中的状态结果；遇到故障持续或读取错误均不会自动重试。实机验证发现上述限制，暂不应将它作为日常自动恢复入口。

`scripts/test_reset_fault_once.py` 的 8 个离线测试覆盖允许写入的控制字、单台/身份/状态门控、已有使能请求拒绝、写入超时后的复位位清除、读取失败和持续故障时不重复复位；已纳入 CTest `reset_scope`。这些测试不等同于实机状态转换通过。
