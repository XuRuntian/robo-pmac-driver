## DC 的已知差异

两份配置的 AssignActivate 都是 `0x0700`。本次两轮均保留 PMAC ESC 寄存器 `09A0=1000000 ns`、`09A4=500000 ns`。

固定版本 IgH 的 `master/fsm_slave_config.c` 将 API 的两个 cycle 参数直接写入 `09A0/09A4`，因此上述传参确实保留了 PMAC 的寄存器值。但 ESI 的 Sync0/Sync1 都是 `value=0, Factor=1`；按同版本 `ecrt.h` 的换算规则：

```text
Sync0 = application period = 1000000 ns
T1 = Sync0 * 1
API Sync1 / ESC 09A4 = T1 - Sync0 + ShiftTimeSync1 = 0 ns
```

**ESI 的默认 Sync1 参数与 PMAC 工程的相位设置不同。** 不能把 XML 的 0 直接理解为停用 DC，也不能把 PMAC 的 500000 ns 称为独立 0.5 ms Sync1 周期。本次没有切换这个参数；后续需将 ESI 的 0 ns 方案作为独立变量进行失能对照，结合调度改进测量，而不是只因一次 OP 成功就认定 DC 合格。

## PDO 数量问题定位

第二轮 debug 日志确认以下写入收到成功应答：

| 对象 | 写入 | OP 中回读 | 备注 |
| --- | --- | --- | --- |

| `1C13:0` | 1 | 2 | `:1=1A00, :2=0` |
| `1600:0` | 5 | 10 | 前 5 项是要求的 RxPDO；后面仍有旧槽内容 |
| `1A00:0` | 6 | 12 | 前 6 项是要求的 TxPDO；后面是 0 |

主站按 SM2 10 字节、SM3 14 字节配置，并取得正确的位置/状态/模式反馈和完整 WKC。这说明配置已影响实际通信，**但不能证明数量字段已按标准更新**。运行中也返回旧数量，已排除“只有退出时数量才被重置”的解释。更像固件对数组数量读取和有效映射数量采用不同处理；仍需要驱动固件资料或厂家确认，尚不能认定为无害的容量回报。

当前没有通过再次清零保留槽、修改 SII/EEPROM、刷固件或保存参数来掩盖这个差异。严格检查继续报错，不把 `hardware_validated` 改为 true。
