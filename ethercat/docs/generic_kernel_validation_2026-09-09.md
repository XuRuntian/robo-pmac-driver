# 普通内核单轴失能验证（2026-09-09）

保留 `7.0.0-31-generic`，最终一轮使用 2 ms 周期，在 DC 稳定后连续观察约 30 秒、15002 个采样，WKC 全部为 3/3，未丢失 OP，DC 监测差值最大 10.879 µs。全程控制字为 0，未使能、未执行电机运动。本结果证明该条件下的失能通信可运行，不代表长期实时性或运动控制已验证。

## 环境与改动

- 单台 Diamond，位置 0，vendor `0x00418108`、product `0x00009252`、revision 1；有线网卡 `enp0s31f6`，e1000e。
- IgH 1.6 源码固定为 `2140c102058bfbabbe0677153850c51c9382343d`。使用 Release 编译，进程局部 FIFO 60、CPU 2 亲和性、内存锁定与栈预触页；退出时恢复。不修改系统全局 IRQ、CPU 调频、Wi-Fi 或内核。
- 固定周期相位提供 application time；发送前以实际时间同步参考时钟，再同步从站时钟。设置主站发送间隔，超期时跳过已错过的周期，避免追赶式连续发送；循环内不输出日志。
- 运行时可选 1/2/4 ms 并同步写入 `60C2`；ESI 模式的 Sync1 参数为 0。原五轴 PMAC 配置保留 1 ms 和原 Sync1 参数 500000 ns，`hardware_validated` 保持 false。
- 首次进入 OP 后任何不完整 WKC 或掉出 OP 均中止。失败后跳过额外外部 SDO 读取，避免与主站重配置竞争；子进程有硬超时和回收机制。
- 读取完运行中的 PDO/周期对象后，要求 DC 差值连续 3 秒不超过 20 µs，才开始正式观察；最多等待 OP 20 秒、进入 OP 后等待稳定 45 秒。正式观察的 100 µs 上限仅为诊断判据。

相位和同步调用顺序参考本地 `build/igh-source/examples/dc_user/main.c` 与 [IgH application interface](https://docs.etherlab.org/ethercat/1.6/doxygen/group__ApplicationInterface.html)。内存预触页参考 [mlockall 文档](https://www.man7.org/linux/man-pages/man2/mlockall.2.html)。普通内核加 FIFO 仍不能提供硬实时保证。

## 尚未解决的 PDO 回读差异

实际 SM 长度为 Rx 10 / Tx 14 字节，domain 共 24 字节，WKC=3，反馈可解码；运行中及退出后读取的前 5 个 Rx / 前 6 个 Tx 映射条目也符合配置。但 `1C12/1C13:0` 仍为 2（期望 1，第二项为 0），`1600:0` 为 10（期望 5），`1A00:0` 为 12（期望 6），尾部存在旧值或零。尚未证明这是固件返回计数问题，也未证明使能时无影响。

因此脚本分别报告 `pdo_payload_matches=true`、`pdo_counts_match=false` 并保留警告。允许继续采集失能时序数据，不作为放行运动的依据；非预期的有效映射、额外非零 PDO 分配或不完整读取仍失败。退出码 0 表示诊断采集完成，应同时检查 DC 判据和这些差异。

## 小范围运动准备与边界

只读参数采集 `motion-setup-2026-09-09-152052` 未写入任何对象。读到 `608F` 编码器分辨率 131072 / 1 转，`6091/6092/6093` 比例均为 1/1；实际机器人机构传动与最终位置单位仍需核实。`607B/607D` 为完整 int32 范围，不能提供本次小行程保护；`6072/60E0/60E1` 为 3000，不能直接当作已确认的安全电流。`605A=2`、`605B=0`、`605C=0` 只是配置回读，尚无实际停车验证。`60FD=0` 本身不能证明急停接线状态。

新增 `CommissioningMotion` 仅用于离线测试：对齐新鲜实际位置后分阶段使能、短距离平滑往返、失能；限制位移、跟随误差、转矩和周期间隔，异常锁存后不自动重新使能。测试覆盖正反向往返、使能位置对齐、状态故障与反馈异常。没有硬件可执行入口调用此运动策略，也没有向真实驱动器发送使能命令。

下一步需要确认电机是否空载并脱开机构、现场可用的急停/断电措施、允许的初次转角；同时核实 PDO 回读差异及驱动器限位、失能退出行为，再接入实际运动入口。2 ms 是目前单轴初次调试的候选周期，不能外推为五轴运行结论。

最终离线验证：`scripts/test_offline.sh` 的 12 组 CTest 全部通过（含 sanitizers），Release 调试程序重新编译通过。最后一次硬件运行后，仅把同等稳定窗口判断提取为 `StableWindow` 并添加边界测试；最终编译产物尚未再次上硬件运行。
